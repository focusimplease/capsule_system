## 计划摘要

胶囊系统第一版采用面向单个用户、由通用 Agent 基座驱动的 Python 模块化单体。当前 Agent 根据 `capsule-system` Skill 理解用户意图，通过稳定的 `capsule` CLI 调用 Python 完成确定性操作；Python 返回机器可读结果或 `next_action`，由当前 Agent 继续完成语义任务。Codex 是开发与主要测试环境，Hermes 是兼容性测试环境，业务核心不依赖任何一方的内部实现。

系统接收纯文本、PDF、独立图片、音频、视频和网页 URL，只长期保存文字、来源 URL 和最终业务记录。飞书知识库与云文档保存主题页、概念页和衍生证据；飞书多维表格保存索引、处理结果、审核项、审核决定与关联关系。第一版不建设 SQLite 可靠性层，不保存持久操作 ID、中间状态、恢复位置或检查点。一个任务必须在当前执行中完成，并以成功、生成审核项或失败结束。

## 交付形态与运行驱动

胶囊系统不是常驻 Web 服务，也不是一组需要用户手工拼接的 Python 脚本。第一版开发的是一套由兼容 Agent 基座承载交互、由 Skill 编排、通过稳定 CLI 调用 Python 的 SE 产品源码。

### 运行主线

```text
用户发送自然语言
        ↓
当前 Agent 识别用户意图并加载 capsule-system Skill
        ↓
Skill 调用 capsule CLI 完成当前确定性步骤
        ↓
Python 校验、提取或准备结构化结果
        ↓
CLI 返回结构化 next_action
        ↓
当前 Agent 按 Skill 完成图片理解、知识比较或页面组织等语义任务
        ↓
Skill 把结构化结果提交给 CLI
        ↓
Python 校验结果并推进状态
        ↓
完成 / 生成审核项 / 失败 / 返回新的 next_action
```

这是一条由当前 Agent 主控、在 Agent 与 Python 之间往返的循环。第一版不让 Python 绕过当前 Agent 再直接调用另一套通用大模型 API。需要模型能力时，CLI 返回结构化 `next_action`，其中包含动作代码、必要上下文、期望结果 Schema 和允许的后续动作。当前 Agent 按 Skill 完成该动作后，再通过 CLI 提交结构化结果；Python 校验 Schema、证据引用和策略约束，只有通过后才能改变证据或知识页。

一次完整任务可以连续执行多个 `next_action`，但所有往返都必须在当前任务中结束。执行期间的中间数据只存在于当前会话、内存或受控临时目录中，不建立可跨会话恢复的工作流。需要人工判断时，系统保存审核项作为本次任务的最终结果；用户作出决定后，由 Agent 读取审核项并启动一个新任务。失败或会话中断时清理临时数据，用户重新提交资料或重新发起操作。

### 各层职责

| 层次 | 核心职责 | 不承担的职责 |
| --- | --- | --- |
| 当前 Agent 基座 | 接收自然语言、执行 Skill 指定的语义任务、决定下一次工具调用并向用户展示结果 | 不绕过 CLI 直接改变业务数据，不自行执行不可逆操作 |
| `capsule-system` Skill | 识别胶囊系统意图、编排 `next_action` 与 CLI 往返、规定追问和审核展示方式 | 不保存业务状态，不决定合法写入，不把 Prompt 当作全局规则数据库 |
| `capsule` CLI | 提供少量稳定、带版本约束的工具入口，校验请求，返回统一结果和 `next_action` | 不暴露任意内部函数，不依赖自由格式自然语言参数 |
| Python 领域模块 | 实现确定性提取、语义结果校验、知识演化约束、审核规则和最终持久化 | 不主控完整对话，不调用另一套通用 LLM，不保存可恢复的中间流程 |
| 飞书 | 保存知识页、衍生证据、索引、最终处理记录、审核项和审核决定 | 不保存原始附件，不承担运行时检查点或后台任务队列 |

因此，可以把当前 Agent 理解为运行主控，把 Skill 理解为交互与编排方法，把 Python 理解为确定性执行和业务规则边界。Skill 调用稳定 CLI 命令，而不是大量零散脚本或任意 Python 函数；Python 通过结构化返回值说明结果与允许的后续动作。这个边界让 Skill 容易阅读和调整，也让业务约束可以自动测试。

### 本次开发产物

本次 Plan 只规划可以共同运行的产品源码、开发测试与兼容性验证：

1. Python 业务模块和供兼容 Agent 基座调用的 `capsule` CLI。
2. 不依赖特定 Agent 内部实现的 `capsule-system` Skill，以及它引用的命令说明和审核展示说明。
3. 飞书知识库、云文档和多维表格的初始化、权限预检与资源定位能力。
4. 经过标注的验收资料集，以及必要的单元、契约、集成和端到端测试。
5. 面向开发环境的运行、测试与兼容性验证指南。

安装包、安装 Skill、面向用户的环境检查、升级和卸载属于后续发布阶段，不在本次 Plan 中设计。

## 技术上下文

**语言与版本**：Python 3.12

**主要依赖**：Pydantic 2 用于定义 CLI 边界模型；Typer 用于构建 `capsule` CLI；`lark-cli` 1.0.68 作为飞书能力的优先调用入口；`pypdf` 用于读取 PDF 文字层；`httpx` 与 `trafilatura` 用于受限网页获取和正文抽取；Pillow 用于图片输入校验；`faster-whisper`/PyAV 用于音视频转写。通用语言与视觉理解由当前 Agent 基座提供，不在 Python 中另接一套通用大模型 API。

**存储**：飞书知识库和云文档保存用户可阅读的知识页与独立衍生证据；飞书多维表格保存索引、最终处理记录、审核项、审核决定和追溯关系；本地受控临时目录只在一次任务执行期间存在。第一版不使用 SQLite，不保存持久操作 ID、检查点、outbox 或可恢复的中间状态。

**测试**：使用 `pytest` 完成必要的单元、CLI 契约、飞书适配和内容提取测试，并在专用飞书测试空间中运行端到端验收。测试强度采用项目默认要求，不额外建立复杂的测试治理流程。

**目标平台**：单用户本地 macOS 开发环境，可由 Codex 或 Hermes 等兼容 Agent 基座读取 Skill、调用 CLI，并访问飞书测试空间。

**项目类型**：由通用 Agent 基座主控、通过 Skill 和 Python CLI 运行的模块化单体 SE 产品；不建设 HTTP 服务、独立前端或 HTML 审核界面。

**性能目标**：优先保证单份资料在当前任务中确定性完成，而不是追求吞吐量。系统同一时间处理一份资料；对同一飞书资源串行写入；外部调用使用有限重试，不建立后台任务和故障恢复子系统。

**约束**：不持久保存 PDF、图片、音频或视频附件；忽略 PDF 中的图片；不保存网页图片或网页图片 URL；证据与可修改的知识页分开保存；永久删除前必须取得绑定明确对象的确认；单次审核决定不得直接变成全局规则；任务失败或会话中断后由用户重新发起，不恢复执行现场。规划产物的标题、正文、表格说明和结论使用中文，只有必须精确匹配的技术标识保留原文。

**规模与范围**：服务一个个人用户和一个飞书知识空间；只维护主题页、概念页两类知识页；接收六种输入形式；处理三类审核事项；P1、P2 在同一版本中实现；不包含多用户授权、企业级工作流和发布安装。

| 检查项 | 阶段 0 前 | 阶段 1 后的设计依据 |

| II. 用户掌握证据不可逆处置权 | 通过：非结构化的 Agent 指令不能直接触发删除 | 通过：CLI 契约要求删除命令绑定明确对象和用户确认；缺少确认时只返回可展示的后果说明，不执行删除 |
| III. 重要不确定必须交由用户决定 | 通过：无法可靠判断、知识冲突和不可逆操作都会生成审核项 | 通过：审核项是当前任务的终态记录；用户决定由新任务处理，决定和最终结果采用追加记录，并与规则改进候选分开 |
| 证据必须与可修改的知识页分开 | 通过：规划中的飞书职责已经分离衍生证据与知识页 | 通过：每份衍生证据使用独立文档和固定身份；关系记录只连接证据与可修改页面，不覆盖证据 |
| 不保留附件 | 通过：长期存储只接收文字、元数据和 URL | 通过：CLI 与飞书契约禁止二进制和附件字段；成功、生成审核项、失败或会话中断都清理受控临时数据 |

**检查结果**：调研前检查通过，设计后复查也通过，不需要申请宪章例外。

## 复杂度说明

当前设计没有违反宪章，因此不需要填写例外说明。飞书知识库、云文档和多维表格之间不存在共同事务，而第一版又明确不建设持久检查点和补偿子系统。为控制复杂度，系统采用“先在内存完成计算与校验，后集中提交终态结果”的方式缩短写入窗口；写入冲突或部分成功无法在当前任务中安全处理时，生成包含受影响资源和处理建议的审核项，并结束当前任务。这个取舍适合个人知识库第一版，但不提供企业级事务保证。
