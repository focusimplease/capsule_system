## AI-001：初始化后的多维表格无法从飞书页面发现

| 字段 | 内容 |
| --- | --- |
| 编号 | AI-001 |
| 发现日期 | 2026-08-17 |
| 状态 | Clarifying |
| 类型 | 初始化需求遗漏 / 可发现性缺陷 |
| 严重程度 | Medium |
| 发现环境 | 飞书专用验收空间 |
| 影响资源 | `胶囊系统-资料索引-验证` |
| Base Token | `T2gcb1c01a9068sTNi6cqe9wnqb` |

### 问题描述

胶囊系统已经创建并正常使用验收 Base，CLI 也可以通过 token 读取和写入其中的数据。但是，用户打开飞书的多维表格页面时看不到这份 Base，只有取得直接链接以后才能打开。

这会让用户误以为初始化没有成功。系统虽然保存了正确的资源 token，却没有把资源放到用户能够从飞书常规界面重新找到的位置。

### 复现步骤

1. 使用胶囊系统初始化验收环境，并创建或绑定 Base。
2. 确认 `capsule admin check` 和 Base 读写均成功。
3. 打开飞书的多维表格页面查找胶囊系统资料索引。
4. 页面列表中看不到 `胶囊系统-资料索引-验证`。
5. 通过直接 URL 打开后，可以正常查看其中的数据表和记录。

### 期望结果

初始化完成后，用户不需要保存内部 token 或依赖开发对话，也能从飞书的常规入口找到胶囊系统使用的多维表格。初始化结果还应明确返回可打开的资源链接和所在位置。

### 实际结果

- Base 存在，并由当前用户 `用户789601` 持有。
- 飞书搜索接口可以找到该资源，直接链接可以正常打开。
- Base 的 `workspace_token` 为空，没有加入多维表格工作区。
- 飞书搜索结果中的 `last_open_time` 为 0，表示用户此前没有在界面中打开过它。
- 同一用户下还有三份名为 `胶囊系统-资料索引` 的历史 Base，进一步增加了查找时的歧义。

### 影响

- 用户无法确认初始化是否成功。
- 更换会话或忘记直接链接以后，很难找到系统的数据索引。
- 多次初始化可能继续产生名称相近的 Base，用户无法判断哪一份正在使用。
- 当前“初始化成功”的判断只验证资源可访问，没有验证用户能否从飞书界面重新找到资源。

### 待确认的处理方向

下面是候选方向，不代表已经确定的实现方案：

1. 初始化时让用户选择现有 Base，或者选择一个明确的多维表格工作区和目录。
2. 系统创建 Base 后，将它加入用户选定的工作区，或在指定云空间目录中建立快捷方式。
3. 在胶囊 Wiki 中增加一个可见入口，指向系统实际使用的 Base。
4. 初始化完成后返回 Base 名称、直接链接和所在位置，并要求用户完成一次可见性确认。
5. 再次初始化前先查找已经绑定的 Base，避免重复创建名称相近的资源。

### 进入开发前需要明确

- 正式版本默认创建新的 Base，还是要求用户选择已有 Base。
- Base 应当放入多维表格工作区、云空间目录，还是只在 Wiki 中建立入口。
- 用户移动或重命名 Base 以后，系统如何继续定位资源。
- 初始化验收是否必须包含“关闭当前会话后，用户仍能从飞书界面找到资源”。

### 建议验收条件

1. 在一个空白用户环境中完成初始化后，用户可以从约定的飞书入口找到 Base。
2. 用户不依赖初始化对话、环境变量或内部 token，也能重新打开 Base。
3. 初始化结果展示准确的 Base 名称、链接和所在位置。
4. 重复执行初始化不会创建另一份用途相同但名称相近的 Base。
5. `capsule admin check` 同时检查资源访问能力和用户可发现性。
